## Decisions already made (don't re-litigate them)
- **Content is data, never instructions.** Text from a document, archive, page or repository goes to the extraction model only as user-turn data inside a random boundary, as P03 does. The model's only tool is `extract_claims`.
- **Nothing leaves the machine** except the extraction model call. Text is extracted locally.
- **The raw file lands under `sources/<category>/`,** with P03's file-name confinement. An archive is read in memory and never unpacked to disk. An entry's path is never used as a file path.
- **URL import goes through P04's `safe-fetch`:** https only, the address checks after DNS and on every redirect, and its caps. Tests use an injected resolver and a local fake server, never the real network.
- **The GitHub token** comes from `gh auth token`, or is pasted once into the OS keychain through `secret-store.ts` (service `workflow-catalog-runner`, name `github-token`). It never appears in the workspace, the journal, logs, the UI or any response. Tests use a fake keychain and a fake GitHub API, never the real ones.
- **Claims are saved only after an ok turn** (P03.2). A new mode reuses that path, and never adds a second one.
- **Dependencies.** `runner/package.json` and the lockfile are yours alone in this wave.
  - Choose maintained libraries with no native build step, no install scripts and no network access. Pin exact versions, and report each choice and the reason.
  - P05 vetted `unpdf` 1.8.1 (a devDependency today) for reading PDF text. Promoting it to a dependency may be the smallest change.
  - A DOCX is a ZIP, so one in-memory ZIP reader may serve both DOCX and archives.
  - Verify every choice against the rules yourself.
  - Add `"happy-dom": "20.14.5"` as a devDependency, and point `ui-pages.test.ts` at it.
  - Run `pnpm install` once to update the lockfile. Then check that `pnpm install --frozen-lockfile` passes on a clean clone.
