Lesson 0001 · Reviewing agent-built code

Review an overnight agent's work in twenty minutes

One tangible win: by the end you will run a fixed five-step loop on any packet an agent shipped overnight, and write down a decision you can defend without having read every line.

Why this firstEverything else in this course assumes you can look at a night's diff and say "merge", "push back", or "revert" with a reason. Prompt tuning, eve upgrades, and extension reviews all sit on top of this loop.

1. Knowledge: what a review is for

Google's reviewer guide gives the standard: a reviewer's job is to make sure the change improves the overall health of the codebase, not to make it perfect. The guide's ordering is the one we use: design, functionality, complexity, tests, naming, comments, style, consistency, and documentation, in that priority. Read the "What to look for" page once; it is the primary source for this lesson (google.github.io/eng-practices, "What to look for in a code review").

Agents change the emphasis in three ways. They are fast, so scope creep is the most common defect: extra features, extra abstractions, "while I was here" refactors. They are eager to make checks pass, so weakened validators and skipped tests are the second. And they write plausible prose, so an untested prompt change reads as finished when it is not.

2. The five-step loop

  1. Read the report before the diff (3 min). Every packet ends with a run report: what was attempted, what was skipped, what failed. Note every "skipped" and "could not". If there is no report, that is the first finding.
  2. Map the diff to the packet (4 min). Open the packet's acceptance criteria. For each criterion, find the file that satisfies it. Anything in the diff that no criterion asked for is scope creep: it gets reverted or split out, never waved through because it looks nice.
  3. Run the proofs (5 min). Run the smoke test and the packet's fixtures yourself. Do not trust the report's "all green". Watch for validators that were loosened to make a fixture pass (a regex made permissive, a schema field made optional, a test marked skip).
  4. Inspect the three risk surfaces (5 min). Prompts (did any file under the runner's prompt directory change, and does a fixture prove it?), schemas and validators (did any get weaker?), and extension permissions (did the manifest gain a permission or host?). These are the places an agent's mistake costs the most.
  5. Decide and write it down (3 min). One of: merge; push back with a numbered list; revert and re-run the packet with a sharper prompt. Append the decision to the packet file so the next session, human or agent, starts from it.

The runner's planned layout puts prompts in runner/agent/ and skills in packages/job-assistant/skills/; the extension manifest is extension/manifest.json. Lesson 0002 walks those paths.

3. Skill: triage these four changes

Each card describes a change an overnight agent made while working the "job capture" packet. Decide whether you would accept it as is or push it back. Feedback is immediate.

4. Retrieval practice

Answer from memory. Options are the same length on purpose.

5. Do it for real

Next time a packet lands, open the printable checklist, start a twenty-minute timer, and run the loop. Then append two lines to the packet file: the decision and the one thing you would change in the packet's prompt for next time. That second line is how the packets get sharper night over night.
