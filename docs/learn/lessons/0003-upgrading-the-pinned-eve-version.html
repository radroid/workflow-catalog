Lesson 0003 · Bumping the eve pin

Upgrade the pinned eve version without breaking the runner

One tangible win: outline only — this lesson is written after the owner does the first real bump of the eve@0.63.0 pin, so it teaches from an actual diff and changelog instead of a guess.

eve pinned: 0.63.0prev: 0002 · where the prompts live in eve
Why this is a stubeve is in beta and shipped 27 releases, 12 of them API-breaking minors, in the two weeks before this course was written (mvp-spec.md §8). CLAUDE.md's rule is to bump deliberately, with the changelog open, never mid-run — so this lesson can't be written responsibly from memory or prediction. It waits for a real bump to record the real commands, the real breakage (if any), and the real fix.

1. Knowledge: why the pin is exact, and what "deliberately" means

To be written after the first real bump. Will cover: why runner/ and eval-agent/ pin eve with no caret, what "between runs, never mid-run" (CLAUDE.md) protects against for a long-horizon build loop, and where the changelog actually lives for this project's pinned commit range.

2. Knowledge: what a version bump can and cannot be proven by

To be written after the first real bump. Will cover: the smoke test (pnpm typecheck && pnpm test, which runs runner/'s vitest suite and eve eval --strict) as the first gate, why that's necessary but not sufficient for an API-breaking minor, and what else has to be re-checked by hand (mode A's four conditions in runner/README.md, the model-slug allowlist, the build stamp in lib/build.ts).

3. Skill: the change-one-version loop

To be written after the first real bump. Will cover, as a numbered loop like lessons 0001 and 0002: read the changelog for every release between the old and new pin; change the version string in every place it's pinned (runner/package.json, eval-agent/, the lockfile); rebuild and run the full chain; re-run the P02 spike's mode-A checks by hand if a release touches auth, cron, or the chatgpt() model path; commit with the changelog range and the diff that proves it still works.

4. Retrieval practice

To be written after the first real bump. Will cover, as short recall questions like lessons 0001 and 0002: where the pin lives, what the smoke test does and doesn't prove, and which mode-A condition is most likely to silently break on an upgrade.

5. Do it for real

To be written after the first real bump. Will point at the actual bump's PR and diff as the worked example, the same way lesson 0002 points at a real skill file to edit.

Ask your teacherIf you're doing a real bump before this lesson is written, treat docs/spec/research/eve-runtime.md, docs/spec/research/eve-spike.md, and node_modules/eve/docs at the new pinned commit as the sources of truth — never memory — and write down what you find. That record is what fills in section 1 above.
