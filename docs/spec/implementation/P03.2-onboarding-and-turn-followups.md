## Goal

## Deliverables
1. **One turn classifier.**
   - P03's extraction route (`interpretExtractionTurn`) and P02's `checkModel` (`interpretModelCheck`) both move onto P08-A's `runTurn`. It follows eve item 15:
     - ok is a `session.waiting` or `session.completed` boundary, with no failure, no `turn.cancelled` and no abort;
     - a non-empty `input.requested` parks the turn, and it is cancelled through the session.
   - The extraction reads its tool results from the returned events, as `persistedExtraction` does today.
   - Decide whether a provider limit met during a model check or an interactive extraction pauses the budget, which is what `runTurn` does. Record the choice in the report. If they shouldn't pause, add an option to `runTurn` rather than a second path.
   - Behaviour stays the same: every existing extraction and model-check test passes unchanged, apart from its import. The exception is deliverable 5's move of where claims are saved, where each moved check is kept and reported.
2. **P03 round-4 reviewer's nits:**
   1. The on-disk view (`markdownOnDisk`) is sent only up to `MAX_MARKDOWN_BYTES`, and as null beyond that.
   2. On Profile, `run()` clears a stale `editorError` after an unrelated action. Or keep it, with a documented reason, if it still describes the text in the box.
   3. Commit tests for the reviewer's probes 2 and 3 (`clip` in `profile-markdown.ts:353`, and `nestedLine`'s escape at `:131`).
   4. `ui-pages.test.ts` counts the announcements on `#last-action` ("announced once").
   5. The file-edit prefix keeps messages within about 90 characters.
3. **P03 round-4 UI critic's polish:**
   1. When a refused control already has focus (an upload, or Enter in an empty statement), the line carries a short reason, e.g. "Not uploaded: only .txt or .md files can be uploaded.".
   2. Line messages stay within about 80 characters, with the consequence first ("Accepted. Approval withdrawn: “…” needs your answer."). The two-line clamp applies to an inner element, so no third line shows.
   - The 413 upload reason is a plain sentence, not "Request body is larger than 524288 bytes.".
   - At 640 px and below, the tag and the message are separated, so assistive tech doesn't read "LAST ACTIONAn answer is needed.".
4. **happy-dom:** moved to P03.1 (iter 006 decision). P05 owns `runner/package.json` and the lockfile while it runs, and P03.2 runs alongside P05.
5. **Claims are saved only after an ok turn** (P04's T1 rule; `logs/handoff/P04-round-2-review.md`).
   - Today `extract_claims` saves inside its own step (`store.extractClaims` in `extract-claims-logic.ts`). So a turn that fails after the tool ran leaves claims behind, while the page reports a failure.
   - Make the tool verify and return: the quote checks stay. The route saves from that call's `action.result`, after an ok turn, and only for the exact source it asked about.
   - **The onboarding eval.** If its gates assert on what the tool wrote, move each assertion to the tool's returned result, or to a route-level Vitest test. Keep the same checks, never fewer, and report the mapping gate by gate. The gate count must not drop without a named replacement.
